# MY EXPO BAG — 消費者ページ (v1.0.1)

このZIPは **消費者向けのWebページ試作** です。バージョンは1.0.1のまま据え置き、出展者管理・読み取り機能の開発を続けます。

## ファイル構成

- `index.html` — 消費者向けページ（入口）
- `config.js` — ブランド・イベント・商品・価格・カテゴリ・セット割引・ノベルティの仮設定
- `styles.css` — 画面デザイン
- `app.js` — 商品詳細・MY BAG・価格計算・QR画面の動作
- `qr.js` — QR画像を生成するためのライブラリ（MITライセンス、ローカル同梱）
- `release.json` — 最新公開状態の確認用（バージョン表示とは別の配信識別子）
- `assets/` — デモ商品画像・アイコン（SVG）
- `THIRD_PARTY_LICENSES.txt` — QRライブラリのライセンス

※ `admin.html` と `scan.html` は**未作成**です。後から同じアプリに追加します。

## 動作する機能

1. 商品一覧・カテゴリ別表示・商品詳細
2. 商品の追加、点数変更、削除、端末内へのMY BAG保存
3. 通常価格と展示会限定価格の表示
4. 最大3パターンの組み合わせ提案：商品詳細ページに関連セットを表示し、割引があれば「別々に買うより◯円お得」、割引がなければ「2点で合計◯円」を表示
5. 関連商品のまとめてBAG追加。すでにBAGに入っている商品は重複させず、足りない商品だけを追加
6. ノベルティの有無・対象金額に応じた案内
7. `MY BAGを見る` → `購入QRを開く` → 名前・メール登録 → デモ用QRを表示
8. メルマガ同意は別の任意チェックボックス
9. 5種類のカラー設定、および3色を個別指定する仕組み

## おすすめの組み合わせ表示について

- ホームの商品一覧には SET DEALS の独立セクションを表示しません。
- 開いた商品を含むバンドルだけを、**その商品の詳細ページ内**に表示します。対象がなければ提案枠は表示しません。
- **追加セット割引あり**：「別々に買うと◯円 → セット価格◯円」「◯円お得！」と表示します。
- **追加セット割引なし**：「2点で合計◯円」と表示し、取り消し線や架空の節約額、0円お得表示はしません。
- 合計の基準は、各商品を単品で購入する場合の会場販売価格（展示会価格があればその価格）です。
- 割引ありの例：ランタン4,200円＋テーブル5,900円＝10,100円、セット割引10%＝1,010円お得、セット価格9,090円。
- 割引なしの例：トート3,200円＋ボトル2,800円＝「2点で合計6,000円」。デモのDAY TRIP SETは割引率を0に設定しています。
- 複数のセット条件が重なる場合は、MY BAGで商品数量を重複使用しない最大割引を適用します。そのため、表示例のセット割引がほかのセット割引と同時に成立しない場合があります。

## GitHub Pagesでの確認

1. ZIPを解凍します。
2. **解凍後のフォルダの中身**（`index.html`, `config.js`, `app.js`, `styles.css`, `qr.js`, `assets/`）を、新しいGitHubリポジトリのルートにアップロードします。
3. GitHub Pagesを有効にし、公開URLにアクセスします。
4. テスト時は商品をBAGに入れ、MY BAGからQRを開きます。

既存のリポジトリに上書きすると元の`index.html`が置き換わるため、最初は**MY EXPO BAG専用の新しいリポジトリ**を推奨します。

## カスタマイズ（出展者画面ができるまでの仮設定）

`config.js`の `window.MEB_CONFIG` を編集します。

| 項目 | 設定位置・内容 |
|---|---|
| ブランド名 | `brand.name` |
| ロゴ | `brand.logoUrl`（例: `./assets/brand-logo.png`） |
| カラーテーマ | `brand.themePreset`（`natural`,`monotone`,`urban`,`soft`,`active`） |
| 自由カラー | `brand.customColors.main/sub/text`（例: `#315746`） |
| おすすめバナー | `event.banner.enabled` / `productId` / `imageUrl` |
| カテゴリ | `categories`（自由追加可能） |
| 商品 | `products`（`id`が商品コード、通常価格`price`、展示会価格`eventPrice`） |
| 組み合わせ提案 | `bundles`（最大3件、`discountPercent` が割引率。`0` / `null` / 未設定なら割引なしで表示） |
| ノベルティ | `novelty.enabled` / `minSpend` / `name` |

色の試着だけしたい場合は、公開URLの末尾に `?preview=1` を付けると5種類のテーマ切替が表示されます。通常の来場者画面には表示されません。

## 現段階の注意点

- **購入QRはデモ**であり実際の販売・予約は成立しません。サーバーへの注文送信、出展者による読み取り照会、CSV記録、LINE連携、複数端末の同期はこれから実装します。
- QRに入る文字列は `MEB-DEMO:<ランダム注文ID>` のみです。氏名・メール・商品コード・価格などをQRへ直接埋め込んでいません。現段階ではQRから注文内容を復元することはできません。
- 氏名とメールはこのページを開いている間だけ端末メモリに保持され、外部サーバーには送信しません。BAGの品目と数量だけがブラウザの `localStorage` に保存されます。
- フォームのメルマガ同意は出展者画面・データベース連携時に、同意日時・同意内容と併せて記録する設計にします。
- 本番のQR発行・売上確定・ノベルティ交換は、出展者別の認証とサーバー側チェックを実装してから有効にしてください。
- 購入時にCSVをブラウザから直接更新するのではなく、**QR読み取り時にデータベースへ登録・更新し、CSVはその時点の最新データを一括出力**する方針です。

## ホーム画面アイコン（iPhone / Android）

- リポジトリの `index.html` と同じ場所に、利用者がアップロードした `myexpobag_icon.png` を置きます。
- `index.html` の `apple-touch-icon` は、そのファイルをそのまま参照します（iPhone / iPad）。
- Android・PWA向けには `manifest.webmanifest` と、192px・512pxアイコンを同じ階層に配置します。付属のサイズ別画像は、直近のロゴ案を縮小したものです。**GitHub側の `myexpobag_icon.png` に使ったデザインと異なる場合、サイズ別画像も同じ元画像から作り直してください。**
- すでにホーム画面に追加している場合は、古いショートカットを削除してからSafari/Chromeで開き直し、再度「ホーム画面に追加」してください。
- GitHub Pagesの公開URLではHTTPSで表示されます。`manifest.webmanifest` により独立したアプリ風の表示に対応します。オフライン対応は未実装です。

## ホーム画面から開いた場合の最新版への更新

- `index.html` は起動時に軽量な `release.json` をオンラインで確認し、その公開識別子をクエリに付けて `config.js`、`app.js`、`qr.js`、`styles.css` を読み込みます。これにより古いブラウザキャッシュを使い続ける可能性を減らします。
- 開いているアプリも、再び前面に戻った際（最低45秒間隔）や使用中の約2分間隔で `release.json` を確認します。最新版なら不要な再読み込みはしません。**GitHub Pages公開時の反映遅延やオフライン中の更新は避けられないため、秒単位の即時反映は保証できません。**
- 画面閲覧・買い物中は、更新を検出すると自動で新しい画面を読み込みます（MY BAGは端末に保存済み）。氏名等の入力フォームや注文QRを開いているときは、途中内容を消さないため、**「更新する」ボタン**を表示して選択してもらいます。QRはデモで、ページ更新後は再生成が必要です。
- **以後、新しいコードや商品設定を公開する際は、`release.json` の `build` 値も必ず変更して同時にアップロードしてください。** ユーザー向けバージョン表記は引き続き `1.0.1` に固定します。
- 初回のこの更新は、元の`index.html`自体がキャッシュされていることがあります。更新後一度Safari/Chromeでページを再読込してください。それ以降の公開では上記の確認機構が働きます。通常はホーム画面への再追加は不要です。
- 現段階の更新確認は**GitHubの公開ファイル更新**が対象です。将来、出展者の管理画面から商品・在庫・価格をリアルタイム変更するには、Firebaseのデータ監視機能を別途接続します。

## GitHubに更新分だけ反映する場合

差し替えるのは `index.html` / `app.js` / `styles.css` / `config.js` / `README.md`、新規追加は `release.json` です。**既存の `myexpobag_icon.png` / `myexpobag_icon_192.png` / `myexpobag_icon_512.png` / `manifest.webmanifest` は変更しません。** `config.js` に独自の商品設定を書き込んでいる場合は、上書きで消えないよう、既存設定を残して `discountPercent:0` の記載だけ合わせてください。
